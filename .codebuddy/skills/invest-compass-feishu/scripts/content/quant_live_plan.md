# 量化模型实盘方案

> **目标**：在智投罗盘网站上实现 A股量化策略自动执行交易
> **第一阶段**：AKShare 真实行情 + 同花顺模拟盘
> **第二阶段**：策略成熟后对接中信证券实盘

---

## 一、总体架构

```
┌──────────────────────────────────────────────────┐
│               智投罗盘 /quant 页面                 │
│  策略管理 → 信号生成 → 订单管理 → 盈亏分析         │
└──────────┬──────────────────┬────────────────────┘
           │                  │
     ┌─────▼─────┐     ┌─────▼─────┐
     │  AKShare   │     │  同花顺    │
     │ (行情数据)  │     │ (模拟交易) │
     │ 免费开源    │     │ 需研究对接 │
     └───────────┘     └───────────┘
```

**数据流**：AKShare 获取实时行情 → 策略引擎判断买卖信号 → 同花顺模拟盘下单 → 回写成交结果到网站

---

## 二、技术栈

| 组件 | 技术 | 说明 |
|------|------|------|
| 行情数据 | AKShare | Python库，免费A股实时/历史行情 |
| 数据桥接 | Python HTTP API | AKShare 是 Python 库，需在 Node.js 后端通过子进程或 HTTP 桥接 |
| 策略引擎 | TypeScript | 前端策略逻辑，定时轮询行情判断信号 |
| 模拟交易 | 同花顺模拟盘 | 需研究同花顺是否提供 API 对接，如无则自建模拟交易引擎 |
| 数据存储 | Firestore | 策略配置、交易记录、权益曲线 |

## 三、AKShare 行情数据接入

### 3.1 AKShare 简介
- **官网**：https://akshare.akfamily.xyz
- **许可证**：MIT（完全免费）
- **安装**：`pip install akshare`
- **支持**：A股实时行情、历史K线、财务数据、指数、基金

### 3.2 关键 API

| 接口 | 说明 |
|------|------|
| `stock_zh_a_spot_em()` | A股实时行情（价格/涨跌幅/成交量） |
| `stock_zh_a_hist(symbol, period, start_date, end_date)` | 历史K线数据 |
| `stock_zh_a_daily(symbol)` | 日线数据 |

### 3.3 桥接方案

AKShare 是 Python 库，Node.js 端不能直接调用。桥接方式：

- **方案 A（推荐）**：Python Flask/FastAPI 微服务，Node.js 通过 HTTP 调用
  - 优点：解耦清晰，可独立部署
  - 命令：`python akshare_server.py` 启动本地服务
- **方案 B**：Node.js 子进程调用 Python 脚本
  - 优点：无需额外服务
  - 缺点：每次请求启动进程，性能差

### 3.4 环境配置

```bash
# 安装 AKShare
pip install akshare flask

# .env.local 无需额外配置（AKShare 无需 API Key）
```

## 四、同花顺模拟盘对接

### 4.1 同花顺模拟盘说明

同花顺（THS）自带模拟交易功能，可通过客户端手动操作。但**自动对接**需要：

- 同花顺是否提供 OpenAPI？—— **同花顺 iFinD 有 API 接口，但需付费**
- 同花顺客户端是否支持自动化？—— **可通过模拟点击/按键精灵实现，但不稳定**
- 替代方案：**自建模拟交易引擎**

### 4.2 推荐方案：自建模拟交易引擎

第一阶段不依赖同花顺 API，在网站内部自建模拟交易：

- **模拟账户**：初始资金可配（默认 100,000 元）
- **下单逻辑**：按策略信号自动"买入/卖出"，记录模拟成交
- **盈亏计算**：按 AKShare 实时行情计算持仓市值和盈亏
- **交易约束**：A股 T+1、涨跌停限制、最小交易单位 100 股

**优点**：
- 完全自主可控，不依赖第三方
- 随时可跑，无需等券商审核
- 策略验证通过后，再对接真实券商

### 4.3 后续对接真实券商

策略在模拟环境验证成熟后：
- 中信证券支持 **QMT（迅投）量化交易接口**，个人可申请
- 需要在中信证券开通量化交易权限
- 将自建模拟引擎的"下单"部分替换为券商 API

## 五、开发阶段划分

### 阶段 1：AKShare 数据接入（约 1-2 天）
- 搭建 Python Flask 行情服务
- Node.js 端对接行情 API
- 替代现有 Mock 行情数据

### 阶段 2：自建模拟交易引擎（约 2-3 天）
- 模拟账户模型（资金/持仓/委托）
- 策略信号 → 模拟下单
- A股交易规则（T+1、涨跌停、100股起）
- 盈亏实时计算

### 阶段 3：策略引擎升级（约 2-3 天）
- 现有 4 种策略模板接入真实行情
- 回测引擎升级（用 AKShare 历史数据）
- 定时轮询执行策略

### 阶段 4：前端可视化升级（约 1-2 天）
- 实时持仓面板
- 交易信号日志
- 模拟账户权益曲线

### 阶段 5：同花顺/券商对接（后续迭代）
- 调研同花顺 OpenAPI 可行性
- 或直接对接中信证券 QMT

## 六、风险与应对

| 风险 | 应对 |
|------|------|
| AKShare 数据延迟 | 用多数据源交叉验证 |
| 模拟交易与实盘差异 | 模拟引擎尽量模拟真实规则（T+1/手续费/滑点） |
| 同花顺无公开 API | 自建模拟引擎兜底 |
| 策略过拟合 | 多周期回测 + 样本外验证 |
