## 工作流

### 流程 A：创建飞书项目文档树

当用户说"创建飞书文档"、"初始化项目文档"、"建立文档结构"、"目录结构"时触发。

1. **用户创建 7 个子文件夹**（在飞书 UI 中）：
   - `01_需求管理` / `02_项目管理` / `03_设计文档` / `04_开发管理` / `05_测试管理` / `06_上线部署` / `07_项目资产`
2. **用户将各文件夹链接（或 Token）发给我**
3. **我执行批量脚本**，在每个文件夹中创建对应的文档（含一句话简介）

**批量创建命令：**
```powershell
python .codebuddy/skills/invest-compass-feishu/scripts/batch_create_docs.py <文件夹Token> 01_需求管理
```

#### 📐 文档排版规范（Markdown 渲染）

创建文档时**必须使用美观格式**，用 `create_named_doc.py` 配合 `.md` 内容文件，
脚本会把 Markdown 渲染成飞书丰富的块类型：

| Markdown | 飞书效果 |
|----------|---------|
| `# 标题` | heading1（大标题） |
| `## 标题` | heading2（章节标题） |
| `### 标题` | heading3（小节标题） |
| `- 列表项` | 项目符号列表（可缩进嵌套） |
| `---` | 分割线 |
| `**粗体**` | 文本加粗 |
| `【章节】` | 加粗文本 |

**命令：**
```powershell
python .codebuddy/skills/invest-compass-feishu/scripts/create_named_doc.py <文件夹token> "<标题>" <内容.md>
```

内容文件建议用 `.md` 扩展名，遵循上述 Markdown 语法排版，避免纯文本堆叠。

### 流程 B：草稿想法 → 多维表格

当用户在飞书中草稿文档里记下了零散想法，说"整理想法"、"写入多维表格"、"提取需求"、"草稿汇总"时触发。

#### 草稿格式（两种都支持）

**方式 A：飞书任务列表**（推荐，在草稿中按 `Ctrl+1` 或点工具栏的任务图标创建）

写标题，下面添加任务项即可：

```
新功能想法
☐ 能将草稿中想法，整理汇总到飞书多维表格里面
☐ 飞书文档的目录都完善了吗
```

**方式 B：Markdown 列表**

```markdown
# 标题
- 想法1
- 想法2
```

#### 执行命令

```powershell
python .codebuddy/skills/invest-compass-feishu/scripts/draft_to_bitable.py <文档ID>
```

默认草稿 ID：`Dbhudc7SEoXNsMxFZKociCL5nSd`

脚本自动完成：读取文档 → 解析任务列表项 → 归类模块 → 判断严重等级 → 写入 Bug 跟踪表 → 在草稿末尾追加 ✅ 已整理标记。

### 流程 C：自然语言录入需求/Bug

当用户说"记个需求"、"提个bug"、"加个功能"、"发现个问题"、"新想法"时触发。

AI 自动执行：
1. **从自然语言提取**标题、类型（需求/Bug）、描述、优先级
2. **展示整理结果**让用户确认
3. **写入多维表格**（调用 Bitable API）

#### 优先级/严重等级规则

Bug 跟踪表（严重等级）：
| 关键词 | 等级 |
|--------|:----:|
| 崩溃/阻塞/数据丢失/致命 | P0 |
| 核心功能不可用/严重 | P1 |
| （默认）功能异常但可绕行 | P2 |
| UI/文案/体验优化 | P3 |

需求表（优先级）：
| 关键词 | 优先级 |
|--------|:------:|
| 紧急/立刻/马上/崩了/阻塞 | P0 紧急 |
| 重要/核心/优先/尽快 | P1 高 |
| （默认） | P2 中 |
| 优化/不急/可延后 | P3 低 |

#### 对话示例

```
用户：记个需求，持仓页面加个收益率曲线图
AI：  已整理：
      类型：需求 → 编号 REQ-008
      标题：持仓页面增加收益率曲线图
      优先级：P2 中（可根据紧急程度调整）
      确认后写入多维表格？
用户：确认
AI：  ✅ 已写入多维表格
```

### 流程 D：更新文档内容（代码变更 → 产品说明 + README 同步）

当代码功能变更后，AI 必须同步更新以下三处，保持文档与代码一致：

| 变更类型 | 必须同步更新的位置 | 内容 |
|---------|------------------|------|
| 新增/修改功能模块 | 飞书产品说明 `ASp8dlNAEo9aCFxJT2cciZt4nuc` | 功能模块章节 + 待办规划 |
| 新增/修改功能模块 | `README.md` | 功能模块表格 + 项目结构 + Mock 数据 |
| 新增页面路由 | 飞书产品说明 + README | 路由表 + 页面列表 |

**同步步骤：**

1. **分析代码变更**：确定新增/修改了哪个模块，涉及哪些页面/组件/数据
2. **更新飞书产品说明**：用追加方式写入对应章节（heading3 + 文本块）：
   ```powershell
   python .codebuddy/skills/invest-compass-feishu/scripts/update_doc.py ASp8dlNAEo9aCFxJT2cciZt4nuc "<章节标题>"
   ```
   （或运行专门的章节脚本，如 `quant_guide_doc.py`）
3. **更新 README.md**：同步修改功能模块表格、项目结构、Mock 数据说明
4. **提交代码时包含文档更新**（README 随代码一起 commit）

**已内置的文档脚本：**
| 脚本 | 用途 |
|------|------|
| `create_named_doc.py` | **创建**新文档（支持 Markdown 渲染）`<文件夹token> <标题> <内容.md>` |
| `update_doc.py` | **覆盖更新**已有文档（清空重写）`<文档ID> <内容.md>` |
| `delete_docs.py` | **删除**文档 `<文件token>...` |
| `list_docs.py` | 列出项目文件夹下所有文档 |
| `create_doc.py` | 创建/追加飞书产品说明文档（旧版） |
| `update_bug_status.py` | 更新 Bug 跟踪表状态 |
| `cleanup_tmp.py` | 清理项目临时文件（替代 cmd del） |
| `feishu_token.py` | Token 管理（app + user 双模式） |

**⚠️ 强制规则（涉及文档更新都必须遵守）：**
1. **优先在原文档上修改**：已有文档要用 `update_doc.py` 覆盖更新，**禁止新建重复文档**。只有目标文档不存在时才创建。
2. **代码变更** → 同时更新飞书产品说明（对应模块章节）+ README.md（功能表格/结构/Mock 数据）
3. **用 skill 操作了飞书文档/表格** → 若涉及功能或结构变化，同步更新产品说明 + README
4. **新增文档/脚本** → 更新本文档的「脚本清单」和「文档目录结构」
5. 两处文档缺一不可，否则视为文档未同步

## 异常处理

| 场景 | 处理方式 |
|------|----------|
| Token 过期 | 自动用 refresh_token 刷新；30 天后需重新授权 |
| 文档创建失败 | 检查文件夹 Token 和 docx:document 权限 |
| 多维表格写入失败 | 检查字段名称是否匹配、单选值是否在选项列表中 |
| HTTP 429 限流 | 脚本已内置 1.2 秒间隔，如仍触发可手动降速 |
| Windows 编码 | 所有脚本已设置 UTF-8 输出 |
